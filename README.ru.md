# Разблокировка BIOS AMD BC-250

[![релиз](https://img.shields.io/github/v/release/kalpakprod/amd-bc250-bios-unlock)](https://github.com/kalpakprod/amd-bc250-bios-unlock/releases) [![лицензия](https://img.shields.io/github/license/kalpakprod/amd-bc250-bios-unlock)](LICENSE) [![плата](https://img.shields.io/badge/плата-ASRock_BC--250-blue)](https://github.com/kalpakprod/amd-bc250-bios-unlock)

Взламываем BIOS платы ASRock BC-250 ради одной цели: **блок кодирования VCN,
включённый в прошивке**. Патчи UEFI/DXE, DXE-драйвер с нуля, воспроизводимые
сборщики образов, строгий предполётный контроль и безопасный протокол прошивки
EEPROM — всё проверено на реальном железе программатором.

Состояние на 2026-09-24: корень LZMA исправлен и подтверждён железом, клин
DXE делится пополам по лестнице из 5 ступеней. На чипе сейчас `v006r-noop`,
его вердикт холодного старта решит следующую прошивку. См. [лестницу](#лестница).

> **Риск кирпича.** Все образы экспериментальные. Для прошивки нужны
> программатор (CH341/CH347 + прищепка SOIC), полный проверенный дамп ВАШЕГО
> чипа и отработанный путь восстановления. Нет пути восстановления — нет
> прошивки. Детали: [docs/01-flash-protocol.md](docs/01-flash-protocol.md)
> (пока на английском).

## Откуда идеи

- **Сама плата.** В пред-дампе уже живут community-драйверы DXE
  (`MeiMeiDXEv3_SMU_Core_Unlock` + `SMU_Patch`) того же размера, что наш.
  Разблокировка из UEFI на этой exact плате — проторённая земля.
- **SMU-кампании D-серии** (d5–d19, наша ранняя работа): доказали, что раннее
  касание SMU в DXE грузится (D10R), что заголовок LZMA с неизвестным размером
  убивает загрузку (D5–D7 → фикс D8), и какие записи гаскета вешают SMU (D12–D19).
- **USB/Linux-пробы** (probe1–probe4): probe3 доказала, что сырое чтение
  набора clock-plan/SMU через `0xB8/0xBC` вешает плату даже после полной
  инициализации, — правило, которое соблюдает наш драйвер (только адреса
  mailbox, всё остальное через Q3 `0x2A`).
- **Комьюнити:** [bc250-collective/amd_smu_reverse_engineering](https://github.com/bc250-collective/amd_smu_reverse_engineering)
  (библия реверса SMU), [thelamer/bc250-vcn](https://github.com/thelamer/bc250-vcn),
  [Shalasere/bc250-vcn-research](https://github.com/Shalasere/bc250-vcn-research),
  [MTSistemi/bc250-vaapi](https://github.com/MTSistemi/bc250-vaapi),
  [Hexxeh/bc250-efi-core-unlock](https://github.com/Hexxeh/bc250-efi-core-unlock).

## Во что упёрлись (честно)

1. **Вис LZMA с неизвестным размером.** Наш пересборщик капсулы (Python `lzma`,
   `FORMAT_ALONE`) писал в заголовок размер `0xFFFFFFFFFFFFFFFF`. Декодер PEI
   платы его отвергает: первое мигание, дальше ничего — до запуска любого DXE.
   Доказано побайтово, подтверждено железом, лечится 8 байтами. Вся история:
   [docs/05-lzma-lesson.md](docs/05-lzma-lesson.md).
2. **Лестница клина DXE.** С грузящимся DXE плата встаёт до видео и LAN.
   Подозреваемые по порядку проверки: код драйвера против хирургии FV (v006r,
   на чипе) → позиция диспатча (v007) → сырые чтения (v008) → время диспатча
   (v009). Каждая ступень меняет ровно одну переменную.
3. **Позиция диспатча.** Наш первый слот был ПЕРВЫМ драйвером TRUE-пула —
   раньше PCI, видео, LAN и всего чипсета AMD. Карта пофайлово:
   [docs/02-uefi-layout.md](docs/02-uefi-layout.md).

## Лестница

| образ | sha256 (коротко) | что | вердикт |
|---|---|---|---|
| v004 | `98b9c2bd…` | драйвер route-B, баг LZMA | прошит, 1 мигание (экспонат) |
| v005 | `2fadb173…` | v004 + явный размер LZMA | прошит, 2 мигания, нет LAN/видео |
| v006r-noop | `6500bea5…` | v005 + заглушка входа (контроль) | **на чипе, вердикт ждём** |
| v007-active | `9d249397…` | тот же драйвер, в конце тома | staged |
| v007r-noop | `0133a34b…` | noop, в конце тома | staged (если v006r встанет) |
| v008-secure | `c935e3ec…` | драйвер только с безопасными чтениями | staged (если v007 встанет) |
| v009-rtb | `56df6244…` | последовательность на ReadyToBoot | staged (если v007+v008 встанут) |

Образы лежат в [релизах](https://github.com/kalpakprod/amd-bc250-bios-unlock/releases)
аттачментами (никогда в git). Каждый образ: полные 16 МиБ, собран из одного
проверенного дампа, публикуется со своим манифестом `.build.json` и SHA256SUMS.

## Состав

- `tools/` — воспроизводимые сборщики, предполётный контроль из 10 ворот,
  стенд драйвера OVMF, проверка VCN после прошивки. Старт:
  [tools/README.md](tools/README.md) (пока на английском).
- `src/Bc250VcnUnlockDxe/` — исходники DXE-драйвера (route-B, secure,
  ReadyToBoot) + рецепт сборки EDK2.
- `docs/` — протокол прошивки, карта UEFI, набор записей драйвера, метод
  проверки VCN, урок LZMA (доки пока на английском, перевод следом).

## Воспроизвести за 5 минут (без железа)

```sh
# 1. Забрать аттачменты v1.0.0 (как минимум образ v004)
# 2. Пересобрать v005 и v006r побайтово:
PYTHONPATH=tools python3 tools/build_v005_lzma_explicit.py
# -> 2fadb173251eb4a44aa9da371f37207efb0f276f8d509926083bfa5a64c03406
PYTHONPATH=tools python3 tools/build_v006_noop.py
# -> 6500bea5b01ea1dcc540939d65faa9cc0ec0f2505a5fcb3e358622803b85bb27
# 3. Увидеть, как v004 ПАДАЕТ на LZMA-воротах префлайта, а v005 проходит:
python3 tools/verify_candidate_preflight.py --help
```

Со своим дампом на 16 МиБ (`BC250_BASE`, `BC250_PRE_SHA`) сборщики append
(v007–v009) работают на ВАШЕЙ базе. Чужой дамп не прошивайте никогда —
NVRAM и данные платы различаются.

## Нам нужна помощь

Откройте issue, если можете двинуть любой из пунктов:

1. **Клин DXE.** v005 встаёт до видео/LAN. Анализ записей против владельцев —
   в `docs/03-route-b-driver.md`. Второй взгляд на механизм гонки с SMU (или
   UART-мод под POST-коды!) разблокирует нас.
2. **VCN на стороне Linux.** Когда ступень загрузится, `tools/postflash_vcn_check.py`
   судит железо — проверьте 16 маркеров и путь привязки amdgpu/VCN.
3. **Тестеры с железом.** Владельцы BC-250 + программатор SPI, готовые шить
   staged-ступени с чтением, — лестница спроектирована именно под это.
4. **История.** У нас 60+ старых образов (D-серия, OC, APCB) с тонкими
   манифестами — помогите связать сирота → скрипт → вердикт.

Связь: issues этого репозитория. PR приветствуются (скрипты и доки; полные
дампы в PR нельзя — см. `.gitignore`).
